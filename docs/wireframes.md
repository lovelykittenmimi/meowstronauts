## 1. 共用骨架

四種尺寸共用同一組元件，只換排列與尺寸：

```
┌──────────────────────────────────────────────┐
│ HUD：⚡ 💧 🛡️ ｜ 🥕 ❤️ 🔬 ｜ 🎒 8/20        │  ← 固定，不捲動
├──────────────────────────────┬───────────────┤
│ 左欄（可捲動）                │ 右欄（固定）   │
│  SOL 3 / 7      ☀️ 今日天氣   │  貓咪立繪／頭像 │
│  ┌────────────────────────┐  │  一句台詞      │
│  │ 事件卡                  │  │  今日名詞 chips │
│  │ 插圖＋兩句簡報           │  │  背包進度      │
│  └────────────────────────┘  │               │
│  ┌────────────────────────┐  │               │
│  │ 選項 A                  │  │               │
│  ├────────────────────────┤  │               │
│  │ 選項 B                  │  │               │
│  ├────────────────────────┤  │               │
│  │ 選項 C                  │  │               │
│  └────────────────────────┘  │               │
└──────────────────────────────┴───────────────┘
```

**核心原則**

1. HUD 永遠單列、永遠可見；遊戲區自己捲動，頁面本身不捲動。
2. 左欄是「讀＋選」，右欄是「誰在說話＋去哪裡複習」。手機最窄時右欄整個收起，不硬塞。
3. 三個選項永遠同時可見，或至少第一個選項與「下滑還有更多」的提示同時可見；不能讓兒童以為只有一個選項。
4. 任何面板（知識卡、背包）打開時，背後的遊戲狀態不重算、不重置。

## 2. 尺寸與佈局判定

PLAN 6.8 的斷點以寬度分；實作時**高度才是主要變數**，因為 844×390 的寬度落在 `md`、高度卻只有 390。實際規則：

| 模式 | 條件 | 代表尺寸 | 右欄 | 事件插圖 |
|---|---|---|---|---|
| **A 緊湊橫放** | 橫向且高度 < 440px | 568×320、667×375、844×390、932×430 | 有，寬 280px；寬 < 680px 時整個收起 | 高 140px，cover 裁切 |
| **B 標準橫放** | 橫向且高度 440–700px | 1024×768 | 有，寬 360px | 高 200px |
| **C 寬螢幕** | 橫向且高度 > 700px | 1440×900、1920×1080 | 有，寬 400px | 高 240px |
| **D 直向** | 高 > 寬 | 390×844 | — | 不載入遊戲 |

- CSS 用 `@media (orientation: landscape) and (max-height: 439px)` 判 A，其餘橫向判 B/C，`min-width: 1280px` 判 C。
- 內容最大寬 1100px 居中；背景 16:9 場景圖滿版。
- 左右 padding：A 12px、B 24px、C 32px；再各加 `env(safe-area-inset-left/right)`。

**數值**

| 項目 | 規格 |
|---|---|
| HUD 高 | 52px；資源圖示 20px、數字 15px 粗體；🎒 觸控區 44×44 |
| 欄距 | 12px |
| 左欄 | `minmax(0, 1fr)`；實際約 464px |
| 右欄 | 固定 280px；`width < 680px` 時 `display: none` |
| 事件卡 | 圓角 16px、內距 12px、插圖 140px、標題 18px、簡報 15px × 2 行 |
| 今日名詞 chip | 高 44px、最小寬 88px、圖示 16px＋文字 14px |
| 選項按鈕 | 高 48px、圓角 14px、間距 8px；左圖示 20px、文字 16px、右側代價 chip 13px |
| 貓咪圖 | 120×160（3:4）圓角 16px；`height < 380px` 時改為事件卡上的 36px 圓形頭像 |
| 台詞 | 15px、最多 2 行、`line-clamp: 2` |

**行為**

- 左欄可捲動，但**三個選項必須在第一次渲染時至少露出第一個完整＋第二個的上緣**；做法是把事件卡簡報壓到 2 行、插圖 140px。
- 選項點擊後就地變成「處理事項中…」0.4 秒，再換結果；不要整頁轉場。
- 結果文字出現在事件卡原位（同一張卡翻面），下方出現［繼續］48px 與貓咪專長按鈕。
- 932×430 同版型，左右留白增加，不放大字級。

```
│        ╰───────╯        │

│   Please rotate         │  18px

│                         │

│                         │
│   不需要重新整理          │  14px silver
│                         │
└─────────────────────────┘
```

- 判斷：`window.matchMedia('(orientation: portrait)').matches` 且 `innerHeight > innerWidth`。
- 直向時**不掛載遊戲主畫面**（不預載事件卡與音效），只顯示覆蓋層；轉回橫向才初始化。
- 覆蓋層 `role="status" aria-live="polite"`；不自動播放聲音。
- 平板直向（768×1024）同樣顯示，但三貓頭像放大到 140px。
- 不可用「請旋轉」擋住已經橫放的桌面小視窗（寬 > 高就不顯示）。

| 項目 | 規格 |

- 術語行內樣式：虛線底線 `2px dashed var(--amber)`＋右側 14px 書本圖示；`padding-block: 2px` 讓觸控區不窄於 32px，若行內太小則同時提供 chip。
- 一篇文字最多 2 個術語連結。

### 10.1 幕 2 動畫規格（2.5D 動態分鏡）

> 目標：把 18 秒的撞擊高潮做成「會動的分鏡」，不是逐格全動畫。
> 預算：11/14 14:00–16:00 撥 1–2 小時（MVP 1 小時；飛船與粒子再加 0.5–1 小時）；16:00 前不穩就退回靜態版。
> 界線：11/14 09:00 後才寫程式；今天只定規格。

**為什麼不是全動畫**

- 全動畫（AI 逐格或 After Effects）要 1–2 天，會吃掉核心循環與影片路徑。
- 2.5D 剪紙／分鏡動畫用現有 07 圖＋一艘 SVG 飛船＋CSS 粒子；06 留給幕 3。2 小時內可完成，風格也一致。
- 低階平板只承受 transform／opacity；不做 WebGL 或大面積 Canvas。

**分階段（避免一次做太大）**

- **MVP（約 1 小時）**：背景慢推＋橘紅風暴 overlay＋警報＋無線電 typewriter＋撞擊白閃／震動；飛船先用簡單剪影或省略。
